# Vendored upstream

`src/vendor/**`, `tests/vendor/**` and `rapidyenc/` are generated by `scripts/vendor.sh`: it
clones infinidysk at the pin, applies `upstream/patches/*.patch` in order, and runs
`scripts/vendor.py <clone> <crate dir>`, which copies the engine crates into one module tree
and rewrites crate paths (it stops if upstream text it rewrites has changed). Never edit the
generated files by hand; change a patch (or add one) and regenerate. CI regenerates and fails
on any difference.

Upstream: https://github.com/infinidysk/infinidysk (MIT, `src/vendor/LICENSE-infinidysk`)

## Vendored

`core`, `yenc`, `nntp`, `stream`, `archive`, `par2`, `testkit` (feature `testkit`), and from
`queue` only `nzb.rs`, `names.rs`, `import.rs`, `import/inspect.rs`; from `vfs` only
`reader.rs`. Upstream tests come along under `tests/vendor/`, except `queue/tests/import.rs`,
which drives upstream's database-backed queue service.

## Mechanical changes made by `vendor.py`

- `crate::` and `infinidysk_*` paths rewritten to `crate::vendor::<module>`.
- `nntp`: `catalog.rs` and its `build.rs` provider catalogue dropped.
- `queue/import.rs`: `infinidysk_db::FirstCheck` replaced by the stub in `vendor/stubs.rs`.
- `vfs`: a local `Error` (no database variant); `Reader::new` made public.
- `nntp/patch/tests.rs`: the crash-child test path follows the module move.
- Test fixtures move under `tests/vendor/fixtures/<crate>/`.

## Monthly sync

1. `scripts/usenet-upstream-diff.sh` lists upstream and SuperFork commits since the pins that
   touch the vendored paths.
2. Take fixes, skip features: move the pin forward (or add patches), rebase the patch series on
   it, run `scripts/vendor.sh`.
3. `cargo test` (the vendored, engine and correctness suites), then rerun the throughput and
   seek-under-load spike against the real providers.
