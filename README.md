# koblibs

Shared libraries for the Kobbler ecosystem: nine Rust crates plus one Svelte component
package, factored out of [kobbler](https://github.com/Kobbler-Media/kobbler),
[kobload](https://github.com/Kobbler-Media/kobload) and
[koblem](https://github.com/Kobbler-Media/koblem) so all three can share them.

Nothing in here is application logic. The crates are deliberately project-agnostic — no
domain types from kobbler or kobload leak in.

> **Not published to crates.io or npm.** Consumers depend on a sibling checkout of this repo
> by path. See [Consuming koblibs](#consuming-koblibs).

## Rust crates

| Crate | What it does |
|---|---|
| **`nats-jobs`** | NATS JetStream job system. A JOBS work-queue stream (each job goes to exactly one worker), an EVENTS pub/sub stream (fan-out to many subscribers), request/reply for synchronous calls like search, plus job-status tracking in PostgreSQL and scheduled/recurring jobs. The backbone of cross-service communication. |
| **`koblem-client`** | Shared wire types and an HTTP client for koblem, the local LLM service. Both koblem itself and its callers depend on this crate so request/response types cannot drift apart. |
| **`kob-providers`** | Provider traits (`LibraryProvider`, release providers) and generic HTTP implementations, so koblem integrations can be swapped without touching call sites. |
| **`kob-gpu-gate`** | A VRAM-budget GPU scheduler for services sharing a machine's cards. There is no heavy/light lane and no global serialisation: a service is admitted onto a card when its tested worst-case peak fits the card's remaining budget, possibly after evicting residents that name it in their `evictable_by` set. Two services on different cards run concurrently; two on the same card co-reside when their peaks fit. |
| **`kob-ffmpeg-sys`** | Raw FFI bindings to FFmpeg (libavformat, libavcodec, libavutil, libavfilter, libswresample, libswscale), generated by bindgen at build time against the system headers. |
| **`kob-ffmpeg`** | Safe Rust wrappers and high-level operations over `kob-ffmpeg-sys`: probing, decode/encode loops, filter graphs, hardware contexts, and Rust-native types for pixel formats, sample formats, channel layouts and time bases. |
| **`kob-ebook`** | Native ebook conversion. Source format → EPUB in-process via [boko], and EPUB → KEPUB via a homegrown kepubifier (koboSpan injection, body div wrapping, OPF cover-image fix). Replaces shelling out to Calibre's `ebook-convert` for the formats boko handles; `native_supports` tells callers when to fall back. |
| **`kob-audio-norm`** | Peak loudness normalisation for short voice-clone reference clips, pure Rust with no FFmpeg dependency. Peak rather than EBU R128 on purpose: clone-from-clip TTS engines reproduce the reference envelope, and R128's dynamic-range compression smears clone character. |
| **`kob-normalize`** | Canonical title normalisation for scene-style release matching — lowercase, diacritic-free, smart-quote-normalised, with predicates that hide the scene's apostrophe/hyphen ambiguity from callers. |

## Svelte package

`@koblibs/ui` (the repo root `src/`) holds the Svelte 5 components and helpers shared by the
three web frontends: `Modal`, `Toast`, `InfiniteScroll`, `SearchSelect` / `MultiSearchSelect`,
`WaveformTrim`, `FaTranscript`, an overlay store, SSE and NDJSON stream parsers, audio/WAV
helpers and formatting utilities. See `src/index.ts` for the full export surface.

## Consuming koblibs

koblibs is **not on crates.io**, so `cargo add` will not find these crates. Consumers declare
a plain path dependency onto a sibling checkout — there is no git dependency and no
`[patch]` indirection:

```toml
# In the consumer's Cargo.toml
[dependencies]
nats-jobs     = { path = "../../koblibs/nats-jobs" }
kob-ffmpeg    = { path = "../../koblibs/kob-ffmpeg" }
kob-normalize = { path = "../../koblibs/kob-normalize" }
```

**So a working checkout of kobbler, kobload or koblem needs koblibs cloned next to it:**

```
workspace/
├── koblibs/     ← this repo
├── kobbler/
├── kobload/
└── koblem/
```

That sibling layout is all local builds need. Docker builds work the same way via an
`additional_contexts` entry pointing at the checkout (`KOBLIBS_DIR`, defaulting to
`../koblibs`) — there is no separate git-branch path to keep in sync, so a change here reaches
every build the moment the sibling checkout has it.

The Svelte package is consumed the same way, as a file dependency:

```json
"@koblibs/ui": "file:../../koblibs"
```

## Build and test

This repo is **not a Cargo workspace** — each crate is standalone, so build and test from
inside the crate directory:

```bash
cd nats-jobs && cargo check && cargo test
cd kob-normalize && cargo test
```

Or across all of them:

```bash
for c in kob-*/ koblem-client/ nats-jobs/; do (cd "$c" && cargo check) || exit 1; done
```

### System prerequisites

- **Rust 1.96 or newer** (every crate sets `rust-version = "1.96"`, edition 2024).
- **FFmpeg development headers** and `pkg-config`, plus libclang for bindgen, to build
  `kob-ffmpeg-sys` / `kob-ffmpeg`. Arch: `sudo pacman -S ffmpeg clang pkgconf`.
  Debian/Ubuntu: `sudo apt install libavformat-dev libavcodec-dev libavutil-dev
  libavfilter-dev libswresample-dev libswscale-dev libclang-dev pkg-config`.
  The other seven crates need none of this.
- `nats-jobs` needs a reachable NATS server and PostgreSQL only to run its integration paths;
  `cargo check` and the unit tests need neither.

`docker-compose.nats.yml` starts a JetStream-enabled NATS on the shared `kob_dev` network for
local development:

```bash
docker compose -f docker-compose.nats.yml up -d
```

### Svelte package

```bash
npm install
```

There is no build step — the package is published as source and compiled by each consuming
SvelteKit app.
